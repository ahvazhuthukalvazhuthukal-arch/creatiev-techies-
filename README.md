## 1. Problem Statement & Threat Landscape

With the proliferation of diffusion-based neural vocoders, zero-shot voice conversion, and high-fidelity text-to-speech (TTS) models (e.g., ElevenLabs, VALL-E, XTTS), audio deepfakes pose critical threats to financial institutions, enterprise authorization channels, and citizen safety:
- **CEO Fraud & Impersonation Scams**: Executive voice cloning used to authorize fraudulent financial transfers.
- **Telecom & Call-Center Exploitation**: Automated interactive voice response (IVR) bypasses using cloned customer voices.
- **OTP & Credential Interception**: Synthetic voices convincing family members or support agents to disclose security tokens.

## 2. Current Implemented Solution vs. Target Architecture

To adhere to **Non-Negotiable Honesty**, this repository strictly distinguishes between what is actively implemented and tested versus what constitutes the long-term research and engineering target (as described in the Creative Techies SIH presentation).

| System Component | Current Active Prototype | Status | Target Architecture (SIH PPT) |
| :--- | :--- | :--- | :--- |
| **Acoustic Classifier** | Pretrained `garystafford/wav2vec2-deepfake-voice-detector` | **ACTIVE & TESTED** | Custom LightCNN-29 / ResNet trained on LFCC + Phase |
| **Feature Extraction** | Spectral Flatness, Spectral Centroid, 20-filterbank LFCC, STFT Phase | **EXPERIMENTAL CONTEXT** | Micro-respiration & biological vocal tremor dynamics |
| **Streaming Ingestion** | WebSocket `/ws/live` with rolling buffer (250ms–3000ms) | **ACTIVE & TESTED** | Real-time WebRTC media gateway |
| **Telecom Integration** | State machine policy simulation (ALLOW, MONITOR, WARN, ESCALATE) | **TARGET TESTBED** | Asterisk / Kamailio PBX inline SIP call intervention |
| **Inference Engine** | PyTorch FP32 on CPU / CUDA + ONNX parity export | **ACTIVE** | ONNX Runtime INT8 Quantized (< 200 ms target) |
| **Audio Privacy** | In-memory byte parsing; zero persistent disk storage | **ACTIVE (DPDP Prepared)** | Hardware KMS encryption + append-only audit trail |

## 3. Strict Scientific & Technical Disclaimers

> [!WARNING]
> **Prototype Score Notice**: The percentage score generated by this system is a raw **synthetic-class model score** derived from softmax probabilities. It is **NOT** a legally calibrated real-world probability of criminal fraud.

> [!IMPORTANT]
> **No Universal Detection**: No acoustic model catches every deepfake. Neural synthesis methods evolve rapidly.
> **Acoustic Features Context**: LFCC and phase statistics currently provide supporting forensic context; they do not constitute an independent trained detector until a downstream classifier is trained on them.
> **No Premature Call Drops**: Never terminate real phone calls based on uncalibrated model scores without multi-window confirmation and human supervisor escalation.

## 5. Quick Start & Installation

### Prerequisites
- Windows / Linux / macOS
- Python 3.11 (Recommended for PyTorch and audio wheel compatibility)

### Setup Virtual Environment

```bash
# Clone or navigate to the repository
cd VocalGuard-AI-V2

# Create virtual environment with Python 3.11
python -m venv venv

# Activate virtual environment
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt
```

## 11. Telephony SIP & Policy Simulation

Simulate how the detector acts within an Asterisk PBX call stream:

```bash
python scripts/simulate_sip.py
```

### Policy Actions:
- `ALLOW`: Low synthetic probability (< 30%). Call proceeds uninterrupted.
- `MONITOR`: Moderate / Inconclusive probability (30% – 50%). Telemetry logged.
- `WARN_VERIFY`: Suspicious probability (50% – 75%). Prompts agent to issue challenge question.
- `ESCALATE`: High score (>= 75%) on a single window.
- `BLOCK_SIMULATION`: Sustained high score (>= 75% for 2+ consecutive windows). Dispatches simulated `SIP_BYE` hangup signal.

## 13. Privacy, Security & Data Protection

- **Zero Audio Retention**: Uploaded and streamed audio resides purely in transient RAM buffers and is immediately discarded after inference. No audio files are written to disk during live analysis.
- **Bounded Buffers**: Rolling streaming buffers are strictly bounded to a maximum of 5.0 seconds (80,000 samples at 16 kHz) to prevent memory exhaustion.
- **No Sensitive Audio in Logs**: Telemetry logs record only timestamps, duration, risk score, and feature metrics. Raw speech waveforms are never logged.
- **DPDP Preparedness**: Designed with Data Protection and Digital Privacy (DPDP) principles in mind, but requires complete KMS encryption and RBAC before enterprise deployment.
